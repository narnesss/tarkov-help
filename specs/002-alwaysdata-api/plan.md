# План alwaysdata API

1. Настроить same-origin Worker proxy API и динамическое включение профилей без пересборки HTML.
2. Защитить Laravel origin общим секретом, передавать проверенный IP для rate-limit.
3. API_ONLY production-конфигурация, SQLite вне каталога релиза и повторяемый deploy без потери ключа/БД.
4. Собрать минимальный API-архив без статических карт/секретов; документация для narnes.alwaysdata.net.
5. Проверить прокси, CSRF/cookie, JSON ошибки, статический экспорт, PHP и CI; обычный push.
6. Автоматически публиковать API по SSH после CI push main, сохранять shared .env/storage
   и внешнюю SQLite; проверять повторные релизы и HTTP-откат кода.
7. Ежедневный SSH-запуск через GitHub Actions для SQLite-снимка на alwaysdata, общая с deploy
   политика хранения: 7 daily, 3 deploy, 100 МиБ; проверять WAL и безопасную очистку.
8. Ручное workflow_dispatch list/check/restore: выбор копии по имени/SHA-256, сохранение
   текущей БД, исключение записей API и проверенный аварийный возврат без изменения .env.
9. Orchid на PHP origin: отдельные редакторы/сессии, CRUD квестов PVE/PVP и файловые справочники;
   первичный импорт без изменения ID прогресса, динамический API контента через Worker,
   новые URL без пересборки, обновление deploy/restore и архитектурных карт.
10. Формы без ввода JSON: справочник торговцев, вложенные текстовые поля, файловые версии
    контента вне релизов; SQLite хранит только ссылки. Двухэтапная публикация совместимого
    чтения и переноса прежних записей; восстановление проверяет все файловые версии снимка.
11. Выбор всех связей по названиям через поисковый индекс SQLite, автоматические ID новых
    квестов/целей/точек, готовые структуры добавления. Большие списки условий разбиты
    на страницы без потерь; проверить браузерные POST с зашифрованным состоянием Orchid.
12. Применить предметный DDL через добавочную Laravel migration: FK предметов/ключей/точек/
    целей/наград, карты и этажи, деревья условий. Идемпотентный импорт исходных файлов,
    формы Orchid с именованными Relation, CAS и публикация совместимых файлов в транзакции.
    Проверить целостность FK, режимы, циклы, повтор импорта, реальные POST Orchid и deploy/restore.

13. Перенести production в MariaDB alwaysdata через MySQL PDO: сохранить все строки,
    PK/скрытые rowid, AUTO_INCREMENT, аккаунты/сессии/прогресс и архивы. Сверить SHA-256
    всех строк каждой таблицы, FK и файловые ссылки до переключения. Закрыть старую
    SQLite, сохранить финальный снимок и .env, перезапустить PHP. JSON остаётся в content.
    Native SQL gzip backup/restore, MariaDB CI и проверка действующей админки.

14. Отдельный `/account`: сводка PVE/PVP по квестам, убежищу и достижениям; заметные
    вход/регистрация во всех шапках. Google/Discord через одноразовый OAuth с привязкой
    к прежнему ID игрока, без автоматического объединения по email; секреты вне Git.
    Проверки SQLite/MariaDB, статического экспорта и реального сайта; [настройка](../player-account.md).

Публикация origin/включение серверных профилей зависят от настроек аккаунтов пользователя.
В репозитории не хранить секреты и не включать API до готовности alwaysdata.
