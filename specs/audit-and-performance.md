# Аудит администрирования и бюджеты производительности

Статус на 2026-10-17: обязательный проектный контракт, не отчёт о внедрении.

## Защищённый аудит Orchid — требуется реализация

С 2026-10-20 визуальные редакторы документов и интерактивных карт используют wiki_document_map_audit:
транзакционные события успеха, отдельные события отказа, HMAC-цепочка и чтение только
с wiki.audit.read. Он не содержит значений формы; очистка через приложение отсутствует.
Общий аудит остальных форм, внешний якорь и согласованные архивы на 180 суток остаются
требованиями ниже и этим изменением не объявляются реализованными.

Проверка SqlDatabaseAudit — проверка целостности SQL, а не журнал действий редакторов.
Общий защищённый журнал остальных форм пока не реализован; существующее разрешение
wiki.audit.read защищает журнал двух редакторов карт.

Журналировать создание/правку/архив/удаление, публикацию/снятие квеста и действия
с игроками: контакты, способы входа, смена пароля и отзыв сессий.
Событие: случайный event/request ID, время UTC, внутренний actor ID/тип, действие,
тип/ID сущности, результат, revision до/после и имена изменённых полей.
Не включать пароли/хеши паролей, коды, токены, cookies, секреты, email/телефон,
полные payload и прогресс. Не записывать даже их прежние значения.
Идентификатор исполнителя — защищённая ссылка, не публичное имя/адрес.

Успешное событие и изменение сущности согласовывать транзакцией/outbox; отказанное
действие регистрировать безопасным отдельным путём без отката журналирования вместе
с неуспешной бизнес-транзакцией. Отсутствие доступа к журналу не скрывать как успех.
Журнал — append-only для приложения, отдельные права чтения wiki.audit.read;
wiki.users не даёт чтение аудита автоматически, разрешение никому не назначается молча.
Редакторы не могут менять/удалять события; защищать целостность цепочкой подписей/hash
и внешним контрольным якорем/копией, иначе администратор БД может переписать всю цепочку.

Проектный срок хранения — 180 суток, включая защищённые копии; это техническая цель,
не утверждение о правовом минимуме. Очистка — отдельная служебная роль с протоколом,
удаление игрока не должно удалять аудит каскадом; actor-ссылки допускают tombstone.
Приёмка: права чтения/отказ, отсутствие секретов, полный набор действий, транзакционный
сбой, недоступное хранилище и обнаружение модификации/удаления/обрыва цепочки.
До появления миграции, записи событий, прав и тестов аудит отмечается как незавершённый.

## Измеримые бюджеты — сначала исходный замер

Не придумывать числа как уже достигнутые SLO. На текущий момент сопоставимый исходный
прогон и утверждённые численные бюджеты не зафиксированы.
До следующей целевой оптимизации заполнить реестр измерений и порогов:
- каталог квестов/поиск/фильтры; полная карточка; карта документов и raid;
- список/редактор Orchid; чтение/запись личного прогресса;
- первичный импорт, повтор без изменений и ограниченный пакет обновлений.

Для каждого сценария записать: revision кода, hash/schema/размер обезличенного набора,
PVE/PVP, конфигурацию PHP/БД/кэша, аппаратную среду, viewport и профиль сети.
Отдельно cold/warm, серверный и браузерный кэш; одинаковые фикстуры до/после.
Поля бюджета: число SQL-запросов (включая служебные), длительность/медиана/p95,
байты JSON до/после gzip, пик RSS процесса и PHP peak memory, общий сетевой вес первого
экрана/страницы и изображений, число запросов и размер крупнейшего изображения.
Для времени собрать не менее 20 повторов и указать разброс; OOM/тайм-аут считать отказом,
не исключать из успешной статистики. Проценты ускорения без исходных чисел не публиковать.

На основании замера задать по каждому полю численный предел и допустимую регрессию,
обосновать запас относительно памяти/CPU/диска alwaysdata; выбрать предельный размер
одного пакета и API-страницы. До утверждения порогов статус бюджета — «не установлен».
Повторять на том же наборе при изменениях запроса, импорта, сериализации, изображения,
кэша или сборки; проверки включать в CI/отдельный воспроизводимый performance-job.
Не использовать реальные пользовательские данные и случайную нагрузку production.

Обязательные качественные ограничения действуют уже сейчас: ограниченные запросы,
пагинация, тайм-ауты, конечные повторы, отсутствие N+1 на растущем наборе, ограниченные
пакеты импорта и отсутствие секретов/прогресса в общем кэше.

## Реализованная оптимизация загрузки, 2026-10-18

Первичный обход публичных семейств: главная, каталог/карточка квеста, предметы, патроны, достижения, торговцы, убежище, крафты, бартеры, БТР, боссы, документы, raid, кабинет, правовые страницы и важные предметы. Исходный замер main `08aa5c4`: Windows/Node 24, обычное соединение без искусственного ограничения, через Cloudflare к PHP 8.4/MariaDB 11.8, PVE. Принудительно production-кэш не очищался. HTTP замеры карточки и проверки версии — по 20 повторов; общие каталоги и важные предметы — тоже по 20. Это время полного HTTP-ответа, не LCP. Размер JSON указан после транспортной распаковки; реальные ответы Cloudflare используют Brotli.

Подтверждены: цепочки поздно обнаруживаемых JS-зависимостей, два последовательных приватных запроса перед отображением, повторная передача полного JSON после отдельной проверки изменённой версии, пересборка готовых публичных представлений после 10 минут простоя.

Код выбранной страницы и его статические зависимости объявляются modulepreload в HTML; чужие страницы и игровые JSON не предзагружаются. Предзагрузка не исполняет модули и не разрешает UI до подтверждения профиля. `config/pages.php` задаёт основной модуль; прежняя JS-карта остаётся для старого HTML. Экспорт учитывает изменения публичных MJS и PageModules, устаревшая сборка без PHP отклоняется. Версии зависимых ресурсов согласованы. Основное изображение карточки предмета не lazy.

Сжатый публичный JSON и агрегат важных предметов хранятся до 86400 секунд, один слот на представление/режим. На каждом чтении сравниваются текущие SQL-ссылки файлов, публикация и ревизии зависимостей: сутки хранения не означают сутки устаревания. Новая редакция заменяет слот; 404 не кэшируется как опубликованный объект. Личные ответы остаются private/no-store. Общие численные бюджеты пока не установлены; результаты одного обхода не считаются SLO для всех страниц.

### Выборочный разбор до заполнения кэша

Дополнительный этап 2026-10-18: PublicJson пропускает содержимое строк через нативный strcspn и не сканирует выбранную коллекцию целиком перед повторным обходом её записей. Декодирование остаётся по одной записи; весь каталог не разворачивается в PHP-массив. Выходные SHA-256 до/после совпали.

Локальный сравнительный прогон: тот же WSL Linux/PHP 8.3.6 CLI на Intel Core i5-14600K (14 ядер/20 потоков, memory_limit=-1), без SQL/HTTP, один и тот же распакованный публичный снимок, 20 повторов каждого сценария, время только PublicJson::select. Выборка справочника: 9 260 142 байта, SHA `fef30bd9318f4737110b903e2dfcb3b0227d7689bfcdf451de7585a52801ef3e`, медиана 177,7 → 95,4 мс, p95 218,2 → 100,4 мс, диапазон 173,3–257,7 → 93,6–113,5 мс.
