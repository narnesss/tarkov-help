# Визуальный редактор карт

В Orchid откройте **Редактор карт** (`/admin/map-editor`). Доступ требует существующего права `wiki.content`. Редактор работает со всеми 13 интерактивными картами, отдельно для PVP и PVE. Выберите этаж и категорию точек; поиск ограничивает видимый слой. «Все этажи» показывает точки на основном плане, новую точку ставят на конкретном этаже.

Выберите метку или запись в списке. Перетащите метку, введите мировые X / высоту / Z либо нажмите «Переместить следующим нажатием» и укажите место. Стрелки у выбранной метки меняют X/Z на метр, Shift — на 10 метров. Этаж можно назначить явно. «Поставить точку» создаёт метку выбранной категории; для предмета вне контейнера выберите предмет из каталога. Категорию существующей точки редактор не меняет: она определяет иконку и предметные связи. Используются прежние иконки проекта.

Изменения поступают на публичную карту после «Сохранить»; один запрос содержит до 100 точек. Архивирование обратимо через «Показать архивные» → «Восстановить». Уход со страницы с несохранёнными правками требует подтверждения. При конфликте версии редактор сохраняет черновик в памяти и показывает серверные координаты: можно явно повторно применить свои изменения или принять серверную версию. После изменения схемы этажей координаты можно скопировать из сравнения и повторить правки на новой схеме. Черновики не записываются в постоянное хранилище браузера.

API редактора закрыт сессией Orchid, правом `wiki.content` и CSRF. `GET /admin/map-editor/data` возвращает каталог; параметры `map` и `mode=regular|pve` выбирают набор и его ревизию. `GET /admin/map-editor/items?search=...` возвращает до 30 предметов. `POST /admin/map-editor/points?map=...&mode=...` принимает `revision`, `definitionRevision` и `changes`. Ошибки валидации — 422, конфликт ревизии — 409; частичная запись запрещена. Публичный API и формат существующих точек совместимы с прежним клиентом.

Запись проходит через `WikiSync`, `ContentDataset` и `WikiImporter::changedPoints`: сначала новый файл в CONTENT_DIRECTORY, затем SQL-ссылка и проекция в одной транзакции, затем существующая инвалидация кэша. ID, квестовые/предметные связи и прогресс сохраняются. Контуры зон перемещаются вместе с точкой. Явный этаж сохраняется в `floorOverride`; техническая отметка `navigator` переносится в `sourceNavigator`, чтобы прежний публичный клиент тоже учитывал этаж. Специальные координаты альтернативных схем документов остаются самостоятельными редакторскими данными.

SVG и иконки редактор получает с `APP_URL` (публичный Cloudflare origin), локальный пакет API содержит Leaflet и код редактора. Для публичного `/assets/raid-maps/*` разрешён CORS без credentials. У JSON API остаётся прежняя политика доступа. Админка не индексируется и отдаётся с `private, no-store`. Версии модулей редактора и их зависимостей вычисляются из содержимого файлов через import map.

Успешные сохранения записываются в существующую HMAC-цепочку `wiki_document_map_audit` в той же SQL-транзакции, по одному событию на точку. Отклонённый запрос оставляет событие отказа без значений формы. Чтение через `/admin/document-maps/audit` требует отдельного права `wiki.audit.read`; редактору оно автоматически не выдаётся. Новых таблиц для этого редактора нет.

Использованы снимки `https://json.tarkov.dev/{regular,pve}/maps`, `/{regular,pve}/tasks`, `/regular/maps_ru` и определения из `the-hideout/tarkov-dev`, commit `97ff6e7a43d03c10f3f7a3165c8dbcdf2193d6b9` (`src/data/maps.json`). SHA256 исходных снимков записан в каждом пакете. Существующие SVG сверены с исходником; графика и иконки не заменяются.

26 пакетов `20261020-map-<map>-<mode>.json` имеют ID **2026102031–2026102056**, отдельная калибровка — **2026102099**. Они добавляют 1390 отдельных спавнов/позиций боссов, уточняют 65 координат и архивируют 808 прежних усреднённых групп. ID архивных групп остаются в данных. Контейнеры, опасные зоны и квестовые места сопоставлены по типу, внешним связям и позиции. Дополнительные редакторские точки не удаляются. Для Резерва уточнены SVG-границы, для Ледокола — преобразование тайлов и границы из определения источника.

Воспроизводимая проверка без сетевых запросов и записи seed:

```sh
node scripts/sync-tarkov-map-points.mjs --source=/absolute/path/to/snapshots
```

Каталог содержит `regular.json`, `pve.json`, `ru.json`, `tasks-regular.json`, `tasks-pve.json`, `definitions.json`. Отчёт появляется в `build/tarkov-map-sync-report.json`, подробности — `build/map-sync-review/`. После применения текущих исправлений повторная сверка должна вернуть ноль добавлений, перемещений и архивирований. `--apply` предназначен только для подготовки нового локального выпуска; существующие пакеты не перезаписываются. Для следующей даты сверки выделяют новые имена и ID пакетов, а не меняют уже применённый выпуск.

На существующем сервере изменения выпускаются штатной командой `php artisan wiki:content-updates` из процесса деплоя, с прежними проверками ожидаемых значений. Seed не подменяет действующие редакторские данные. Перед разрешённой публикацией обязателен согласованный backup SQL и CONTENT_DIRECTORY. Откат интерфейса допускает предыдущий фронтенд/API; откат координат выполняется новым CAS-пакетом с обратными полями из backup, новые точки архивируются. Не удалять действующие файлы контента и не заменять всю БД ради отката этих правок.

Редактор документов `/admin/document-maps` использует такую же раскладку, как `/admin/map-editor`: фильтры и действия сверху, схема слева, свойства и список точек справа. На ширине до 1100 CSS px схема находится над инспектором; до 480 px кнопки и поля переносятся. Кнопка «Показать всю карту» сбрасывает масштаб и прокрутку, схема подстраивается при изменении размера окна. Иконки документов/выходов, связи, отдельное сохранение положения и CAS остаются прежними.

У сохранённой точки кнопка «Удалить точку» открывает подтверждение с её названием. Удаление архивирует всю точку во всех режимах и на всех этажах, включая альтернативные позиции; выход также исчезает с интерактивной карты. ID, координаты и связи остаются для восстановления через карточку сущности. Отмена и ошибка сохраняют несохранённые координаты; конфликт версии требует обновления данных перед повторным подтверждением. POST `/admin/document-maps/remove` проверяет права `wiki.content`, CSRF, принадлежность карте/режиму и CAS; изменение, публикация и защищённый аудит выполняются в одной SQL-транзакции под `WikiSync`. Кнопка скрыта для нового черновика и при старом API без `capabilities.archivePoint`; старый клиент игнорирует новое поле.
