# Карта БД Tarkov Wiki

SEO не создаёт таблиц и не изменяет аккаунты/прогресс. `QuestSeo`, `EntitySeo` и `SiteMap` читают
опубликованные `quests` и версионный payload; `updated_at` используется как lastmod в UTC.
Статический каталог маршрутов задаёт существующие slug, но не разрешает публикацию записи.
`EntitySeo` читает текущие ContentDataset; кэш необходимых предметов разделён по версии
payload каждого квеста, имени БД, CONTENT_DIRECTORY и режиму, TTL — public_cache_ttl.

Пакетный редактор документов записывает до 100 позиций одной SQL-транзакцией под WikiSync
и общей CAS-версией снимка. Ошибка любой позиции или аудита откатывает весь пакет и ссылки
CONTENT_DIRECTORY. Архивирование/восстановление меняет active/archived, сохраняя ID и связи.
Для новой точки clientId сохраняется как external_id `document-editor-<clientId>`;
повтор создания с актуальной версией даёт 409, чтение возвращает clientId для объединения
потерянного успешного ответа. Прежние external_id не меняются. Миграций нет.

Пакеты Берега 2026102301–2026102302 обновляют только статус/видимость 266 существующих
точек в файловых наборах под CAS. SQL ID, координаты, связи и прогресс сохраняются;
новых таблиц и миграций нет. Три ранее отключённых выхода остаются архивными.

Миграция 2026_10_20_000015 добавляет пустую `wiki_document_exit_positions`: FK point_id →
wiki_map_points, map_id → wiki_maps, составной FK (layer_id,map_id) → wiki_map_layers,
unique(point_id,map_id), конечные X/Y в процентах этажа и revision. Данные появляются только
при явном сохранении редактора; прежние точки не копируются и не перенумеровываются.
Таблица — SQL-источник независимой документной позиции, не пересоздаваемая импортом проекция.
Полные MariaDB backup/restore включают её как остальные SQL-таблицы. Документные позиции
остаются в wiki_point_positions, совместимый контент — в CONTENT_DIRECTORY.
Удаление из визуального редактора меняет только active/archived и revision родительской
wiki_map_points; позиции, медиа и связи сохраняются. Публикация отмечает cmsArchived,
инвалидирует публичное представление и фиксирует archive_document/archive_exit с полями
active,archived в wiki_document_map_audit. Отказ аудита откатывает SQL и ссылки на контент.
Откат кода сохраняет таблицу; down удаляет только новые позиции, поэтому после начала
редактирования сначала требуется отдельная SQL-копия. Старый код показывает автопривязку
выходов; для возврата ручных позиций достаточно вернуть совместимый код без переимпорта.

Миграция 2026_10_20_000016 добавляет закрытый wiki_document_map_audit. События создания,
перемещения и отказа содержат UTC-время, actor_ref, ID точки, версии и имена полей, без значений
формы и персональных данных. Успех записывается вместе с изменением, отказ — после отката.
Записи связаны HMAC-цепочкой с APP_KEY вне БД; изменение/удаление через приложение отсутствует.
Чтение отдельным правом wiki.audit.read, которое автоматически никому не назначается.
Автоматической очистки нет; целевой срок — не менее 180 суток. Это журнал только данного
редактора и интерактивных карт (`entity_type={create|update|archive|restore}_raid_point` и `raid_request`), а не завершение общего аудита Orchid или настройка внешнего контрольного якоря.

Визуальный редактор карт не меняет DDL. `content_datasets` хранит актуальную ссылку на файловый `raid/{pve/}<map>.json`; `wiki_map_points` и `wiki_point_world_positions` обновляются ограниченным импортом изменённых ID. Идентификаторы, предметные/квестовые связи и `user_state` сохраняются. Смена координат, явного `floorOverride`, названия, описания и `cmsArchived` атомарна под CAS. Новые точки получают стабильный `editor-<UUID>`; повтор запроса с прежней ревизией возвращает 409. Сверка 2026102031–2026102056 архивирует усреднённые группы, не удаляет их PK и прогресс. Калибровка 2026102099 меняет только параметры отображения в `raid/maps.json`.

Локальные копии изображений из `config/public-media.php` применяются при выдаче публичного
JSON через PublicMedia. Схема SQL, ссылки ContentFiles, payload, ID и отношения не меняются.

348 совпавших точек сохраняют прежние внешние и SQL ID; 28 исходных записей архивируются,

Пакеты ContentUpdates используют существующую wiki_projection_states:
owner_type=content-update, owner_id=номер пакета, content_ref=SHA-256.
Маркер записывается в той же транзакции, что SQL-ссылки на неизменяемые JSON-файлы.
Новые JSON-колонки не добавляются. Архив ошибочной точки сохраняет её SQL/external ID,
FK и личные отметки. Неподтверждённые внешние координаты остаются в файле с reviewReason
и sourceStatus=unverified-coordinates; API их не публикует до редакторского исправления.

Служебные ID точек (`loot-7`, `spawn-14`) локальны для карты. Прежняя SQL-строка и её FK
сохраняются; совпавшая точка другой локации получает новую SQL-строку с external_id
scoped-SHA256(kind, mode, location_id, public_id). wiki_sources связывает каждый указатель
с правильной строкой. ID в JSON и ключах личного прогресса не меняются. Одноразовый проход
repairPointScopes разделяет старые совпадения без перезаписи уже исправленных строк.
Проход фиксирует до 100 исходных точек за транзакцию WikiSync и возобновляется после сбоя.
Он выполняется до общей транзакции пакета контента и не меняет файлы, аккаунты или прогресс.

Миграция `2026_10_15_000004_create_wiki_domain.php` применяет
`database/migrations/sql/2026_10_15_domain.sql`: 45 предметных таблиц с PK/FK/UNIQUE/CHECK
и индексами обеих сторон M:N. Дополнительно создаются `wiki_point_world_positions`
(мировые координаты без вымышленного пересчёта в проценты), `wiki_location_aliases`
(UNIQUE scheme/value), `wiki_sources` (FK на набор и конкретную предметную сущность,
UNIQUE dataset/pointer), `wiki_projection_states` (SHA применённого файла),
`wiki_import_issues` (текст неизвестных ссылок). Предметные таблицы имеют revision,
archived, display_name и Unicode search_text. Имена поиска — производные колонки,
само содержимое связей — обычные FK и атрибуты; JSON-колонок нет.

Ключ — PK/FK item_id → wiki_items; выход — PK/FK point_id → wiki_map_points.
Квест хранит UNIQUE(external_id,mode,version_id) и UNIQUE legacy_quest_id → quests.
Цель хранит прежний external_id; UNIQUE(quest_id,external_id). Точка разделяет режимы
UNIQUE(external_id,mode), общий документный режим — all. Составные FK гарантируют
совпадение локации карты/точки и принадлежность этажа изображению. Родитель группы
связан составным FK с тем же владельцем. Laravel дополнительно запрещает циклы,
смешение режимов/версий и устаревшие revision. Идентификаторы и source_path скрыты
в формах; Relation принимает PK выбранного имени, сервер определяет настоящий FK.
Для строк с составным PK редактор использует внутренний SQLite rowid, не выводя его
в текстовое поле. Удаление заменено архивом; публикация обновляет только выбранный
раздел файла, сохраняя неизвестные поля и прежние ID прогресса.

Контент находится в `content/<первые 2 символа SHA>/<SHA>.json.gz` рядом с SQLite,
на alwaysdata — `/home/narnes/tarkov-data/content`, вне релизов и web root.
JSON квестов и справочников в БД не хранится. Файлы неизменяемы, проверяются по SHA-256;
смена ссылки в БД атомарна и отклоняет устаревшую форму. Все прежние версии остаются,
поэтому SQLite-снимок возвращает прежние тексты сменой ссылок. Проверка/restore бэкапа
проверяют наличие и контрольные суммы файлов. Для переноса на другой сервер нужны
SQLite-снимок **и весь каталог content**. Автоматического удаления старых версий пока нет.
Сессии, права Orchid и личный прогресс используют прежние форматы и контракты.

ID квестов/целей импортируются без замены; создание редакторской схемы не меняет
аккаунты/сессии/прогресс игроков. Импорт firstOrCreate сохраняет правки и черновики.
Снятые с публикации задания остаются в БД, публичный API их не выдаёт.
Rollback запрещён, резервные копии охватывают контент вместе с аккаунтами.
Restore очищает также admin_sessions и remember_token редакторов.

### Оптимизация загрузки 2026-10-18

Схема, ID и связи не менялись. Условное чтение публичного контента сравнивает прежние SQL-ссылки файлов; готовые версии сохраняются в Laravel Cache до суток. Опциональный `state` в ответе сессии использует прежний `StateRepository::all` только для владельца текущей opaque cookie, с теми же value/version; новые поля БД не добавляются.

Рефакторинг редактора и кэша 2026-10-18 не меняет DDL: ContentLinks пакетно читает content_references по PK/игровому значению с прежними kind/variant и правилами архивных связей. ContentFiles возвращает прежний @file:SHA256 после проверки временного файла; SQL остаётся владельцем действующей ссылки. Аккаунты, связи и user_state не перезаписываются.

Выходы и ключи на картах документов: новый read-only view не меняет схему или записи. Требования доступа читаются из wiki_key_usages → wiki_map_points/wiki_items; названия и иконки — из wiki_items/wiki_keys. При отсутствии явных связей используются существующие описания документов; опциональный ключ/обходной путь и явное очищение связей имеют приоритет. Координаты выходов берутся из действующего raid dataset соответствующего режима.

Пакет 2026102001 меняет только шесть наборов raid/{pve/}{shoreline,lighthouse,streets-of-tarkov}. pointChanges проверяет прежние поля перед записью; ID, координаты, связи и пользовательский прогресс сохраняются.
