# Контент сайта и Orchid

Laravel 13 использует Orchid 14.53. Админка работает на PHP-сервере:
локально `/admin`, после публикации — https://narnes.alwaysdata.net/admin.
Вход редакторов отдельный от аккаунтов игроков. Публичной регистрации редакторов нет.

## Первый запуск локально

Сохраните существующие `.env`, `APP_KEY` и SQLite; перед миграцией рабочей базы сделайте
согласованный бэкап. Для нового окружения скопируйте `.env.example`, настройте `DB_DATABASE`
и выполните `php artisan key:generate`. Затем:

```sh
composer install
npm run content:seed
php artisan migrate
php artisan wiki:import-content
php artisan wiki:import-domain
php artisan wiki:reference-index
php artisan orchid:admin
php artisan serve
```

`orchid:admin` интерактивно запрашивает имя, email и скрытый пароль. Не передавайте пароль
аргументом shell и не сохраняйте его в Git. Созданный редактор получает права Orchid
`platform.index` и `wiki.content`. Для дополнительных редакторов можно повторить команду.

## Сущности и связи

Раздел **Сущности и связи** открывает предметную схему SQL (production MariaDB, локально SQLite). Для обычного заполнения
используйте эти каталоги; **Данные сайта** оставлены для дополнительных файловых полей.
Названия, тексты, числа, флажки и списки — все доступные способы ввода. ID и JSON вводить
не требуется. Для одинаковых подписей точек в выборе указаны также локация и режим.

1. В **Предметах** создайте или найдите предмет. В его связанных записях можно открыть
   **Ключи** и добавить специализацию: описание и число использований. Название ключа
   берётся из предмета.
2. В **Точках карты** выберите локацию и режим, заполните название. В связанных разделах
   добавьте **Позиции на изображении** (карта, этаж, X/Y в процентах) либо **Мировые
   координаты**. Это разные системы координат; автоматического пересчёта между ними нет.
   Для документной карты добавьте **Документы в точках**. Новая документная точка попадёт
   в совместимый набор сайта после заполнения позиции и документа.
3. В точке откройте **Спавны предметов**, **Использование ключей**, **Категории точки**,
   **Точки выполнения целей** или медиа. Во всех связях найдите нужную запись по названию.
4. В **Квестах и связях** откройте квест, затем **Цели квестов**. В цели доступны группы
   условий «Все / любое», предметы с количеством и FIR, локации, точки и ключи.
   Группа может содержать дочерние группы. Для условий открытия квеста используются
   **Группы условий открытия** и **Предшествующие квесты** со статусом.
5. В квесте откройте **Наборы наград**, выберите начало или завершение. Внутри добавляются
   предметы, репутация, навыки и открываемые возможности. Например, **Предметы наград**:
   выбрать предмет по имени, задать количество, сохранить.

Список, открытый из карточки, уже ограничен этим владельцем; кнопка **Создать** подставит
его автоматически. Для переноса связи создайте новую и отметьте прежнюю **В архиве**.
Архив можно показать флажком в списке и восстановить. Устаревшая форма запросит обновление.
В прежней карточке квеста есть ссылка **Предметные связи: цели, точки, ключи и награды**.
Прежние текстовые формы продолжают работать и обновляют SQLite при сохранении.

## Основная форма квеста

В разделе **Квесты** есть поиск, выбор режима, создание и редактирование. Записи PVE и PVP
независимы. Можно менять название, торговца, уровень, опыт, описание, цели, награды,
условия открытия, прохождение, медиа и ветки сюжета.
В списке показываются названия торговцев; в форме торговец выбирается из справочника.
Его ID и название не требуется вводить вручную.

Каждая цель представлена строкой с описанием, действием и количеством. ID квеста и новых
целей создаются автоматически и скрыты от редактора. После сохранения
открываются разделы **Подробные условия целей**, **Награды**, **Прохождение и материалы**
и **Остальные поля задания**. В них вложенные записи открываются ссылками, значения
редактируются отдельными текстовыми/числовыми полями и выбором «Да / нет».
В условиях целей выбирайте **Предметы**, **Квестовый предмет**, **Локации**, **Оружие**,
**Ключи** из списков с поиском по русскому или английскому названию. В наградах откройте
**Предметы → Запись → Предмет**, выберите название и укажите количество. Таким же образом
выбираются торговцы, необходимые квесты, навыки, модули убежища и документы.
Список ключей использует каталог предметов, поэтому новый ключ не требует отдельного ID.
Группы альтернативных условий открываются отдельно; их вложенность сохраняется.
Списки более 60 связей открываются страницами, добавление в них также выполняется по названию.
Названия в поиске загружаются порциями, полный каталог не помещается в HTML формы.
Вводить JSON ни в одной форме не нужно. Сложные условия сохраняются при правке основной формы.
Добавление использует готовые варианты с понятными названиями: предмет награды с количеством,
репутация торговца, условие открытия квеста, ключи, место выполнения и другие поля.
Техническое имя поля вводить не требуется. Новые записи получают собственные ID;
ссылки из исходной записи не копируются как новые сущности.
При правке наград форма становится источником наград вместо старых справочных наложений.
Устаревшая вкладка не перезапишет более свежую правку: форма попросит обновить страницу.

ID и режим созданного квеста неизменяемы. ID существующих целей нельзя удалять или заменять:
на них ссылается личный прогресс. Новые цели добавлять можно. Для снятия квеста с публикации
выключите **Опубликован**; запись и прогресс остаются. Черновики не попадают в API.

Новые квесты открываются по `/quests/<ID>`, новые торговцы — `/quests/trader/<ID>`.
Worker проверяет публикацию и выдаёт общую HTML-оболочку, если отдельного экспортированного
HTML ещё нет. Старые красивые URL сохраняются. Оболочки и SEO-метаданные прежних
экспортированных страниц обновляются при сборке; содержимое заданий приходит из файлов контента.
Оболочка запрашивается у ASSETS по `/quest` или `/quests`, чтобы избежать перенаправления
с `.html` при [drop-trailing-slash](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/).

## Остальные данные

Раздел **Данные сайта** содержит 63 исходных набора: карты, предметы, справочники,
вспомогательные материалы. В каждом наборе открывайте нужный раздел и заполняйте значения
обычных полей. Большие списки разбиты на страницы по 60 записей/полей.
Структура и стабильные ID должны соответствовать клиентским модулям сайта.
В наборах `guide/quests-*.json` редактируется контекст каталога (карты, предметы и метаданные);
список заданий берётся через индекс `quests` и файлы, через раздел **Квесты**.

Исходные вспомогательные наборы квестов используются при первоначальном импорте.
После импорта материал конкретного задания редактируется в его записи (`questContent`,
`media`, `gunsmith` и другие поля), а не повторным изменением исходного снимка.
Изображения и SVG по-прежнему являются файловыми ассетами; загрузчик новых файлов
в этой версии не добавлен.

Публичные JSON читаются через `/api/content/data/<путь>.json`. На Cloudflare запрос идёт
через защищённый same-origin proxy. Laravel-страницы используют тот же endpoint локально.
Он не открывает сессию; ответы API имеют `private, no-store`. Общий кэш не содержит
аккаунты редакторов и игроков. Админка использует штатные Laravel cookie/CSRF, собственную
таблицу `admin_sessions` и cookie `wiki_admin_session` с путём `/admin`.
Настройка админской сессии применяется до создания контроллеров Orchid; обычный вход
работает и без флажка «Запомнить меня».

При обновлении страницы данные CMS имеют приоритет над старым браузерным кэшем и внешним
API. **Обновить квесты** перечитывает CMS. При недоступном PHP API клиент использует
статический снимок. В автономном экспорте/Pages без Worker остаются данные снимка.
Для постоянной работы с динамическими данными нужен включённый `API_ENABLED`.
Счётчики квестов и поиск на главной странице также формируются из опубликованных записей.

## Обновления alwaysdata

`npm run package:alwaysdata` готовит сжатые исходные наборы и обогащённые квесты;
архив включает их в `database/content-seed` без SQLite, аккаунтов или секретов.
`deploy.sh` после бэкапа и миграций выполняет `wiki:import-content`, перенос в файлы,
`wiki:import-domain`, индекс названий и публикацию ассетов Orchid. Первый backfill занимает
существенное время на ограниченном CPU; последующие запуски сверяют SHA и сохраняют
существующие связи. CLI показывает справочники, число обработанных квестов и точек.
Для первого большого backfill серверное задание ограничено 60 минутами.
После переноса файлов выполняется `wiki:reference-index`: производный индекс обычных
текстовых названий в SQLite. Он не содержит JSON. Изменения через формы обновляют индекс
в той же транзакции, что и ссылку на версию файла. Повторная индексация сохраняет внутренние
значения уже открытых списков. Архивная отсутствующая связь видна только в прежней записи;
её нельзя выбрать как новую. Проектирование дальнейших связей карты:
[content-relations.md](architecture/content-relations.md).
Повторный импорт добавляет только отсутствующие записи; правки и черновики не перезаписывает.
Первый импорт переносит 1226 записей режимов с прежними ID. Импорт читает наборы порциями,
хранит справочники сжатыми и не загружает все исходные JSON одновременно.

После первого деплоя создайте редактора по SSH командой `php artisan orchid:admin` в активном
релизе. `orchid:install` запускать не нужно: он предлагает стандартную схему `users`, которая
в этом проекте занята игроками. Для больших справочников настройте на PHP origin
`post_max_size=32M` и достаточную память (512M для редактирования крупных JSON).
Админка доступна непосредственно на alwaysdata и не требует proxy-секрета в браузере;
публичный контент и аккаунты игроков продолжают использовать Worker.

Ассеты Orchid генерируются Composer в `public/vendor/orchid`, не коммитятся и не попадают
в Cloudflare `dist`. При restore очищаются сессии игроков и редакторов, отзываются remember
tokens; контент возвращается вместе с согласованным снимком SQLite.

Мобильные дополнения подключает `PlatformProvider::stylesheets()` из `public/admin-responsive.css`;
файл явно включён в API-пакет. Панель действий на узком экране находится перед формой и
переносит кнопки, не перекрывая поля. Таблицы прокручиваются внутри своих блоков, вкладки
и пагинация переносятся. Нижний блок профиля в мобильном меню находится в обычном потоке,
чтобы пункты меню оставались доступны и в альбомной ориентации.
Переопределение `vendor/platform/fields/matrix.blade.php` добавляет
только доступную с клавиатуры обёртку прокрутки: штатные поля, стабильные ID, имена,
обработчик Matrix и защита несохранённых изменений сохраняются. Открытый список Matrix
получает место под таблицей; поля выбора и варианты остаются доступны внутри прокрутки.

## Файлы контента и перенос прежних данных

В SQLite больше не записывается JSON квестов и справочников: колонка `payload` содержит
только строковую ссылку `@file:SHA256`. Версии содержимого находятся в закрытом каталоге
`content` рядом с SQLite, на alwaysdata — `/home/narnes/tarkov-data/content`.
Формат файлов — `<первые 2 символа SHA>/<SHA>.json.gz`. Сжатие экономит квоту хостинга;
контрольная сумма проверяется при чтении. Новый файл публикуется атомарно до обновления ссылки.

При переходе сначала публикуется релиз, который читает и прежний формат, и файловые ссылки.
После проверки этого релиза выполняется `php artisan wiki:content-files --move`.
После завершения перехода эта команда входит в `deploy.sh` и проверяет каждый новый релиз.
Команда переносит текущие значения, включая редакторские правки, сохраняет ID и даты,
при повторном запуске только проверяет файлы. `php artisan wiki:content-files` проверяет,
что все записи уже используют файлы. Не запускайте перенос до публикации совместимого кода.
После обновления релиза через симлинк при старом коде в PHP-кэше перезапустите сайт
в alwaysdata → Web → Sites → Restart и повторите проверку формы.

Старые файлы неизменяемы и не удаляются автоматически: SQLite-бэкап хранит ссылки на них.
Restore проверяет наличие/контрольные суммы файлов и возвращает нужные версии ссылок.
Для внешней резервной копии или переноса нужны **снимок SQLite и весь каталог content**.
Один файл SQLite после перехода не содержит тексты контента. Аккаунты, сессии, права Orchid
и личный прогресс продолжают использовать прежние защищённые форматы хранения.
