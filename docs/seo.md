# Индексация Tarkov Compass

Проверка публичного сайта: 25 октября 2026 года. Изменения применяются после согласованной
публикации API и Cloudflare. Метаданные не гарантируют позиции или включение в индекс.

## Исходное состояние

GET с User-Agent YandexBot возвращал 200 для главной, каталога и `/quests/debut`.
`/sitemap.xml` возвращал 404; canonical отсутствовал. HTML карточки содержал загрузку
задания без H1 и целей. Неизвестный URL корректно возвращал 404. Проверка публичного
HTTP-ответа не подтверждает настройки WAF для настоящих IP робота и состояние индекса.

## Реализация

- `PageSeo` формирует title, description, canonical, Open Graph, Twitter и JSON-LD для
  всех типов страниц. `SITE_URL` — канонический HTTPS origin, по умолчанию
  `https://tarkov-compass.narnesss.workers.dev`. Назначение `APP_URL` в CSRF сохраняется.
- ID-алиасы квестов и торговцев указывают canonical на существующие slug. Игровые страницы PVE
  имеют адрес без параметра, PVP — с `?mode=regular`; каталоги сохраняют `page`.
- `QuestSeo` читает опубликованные записи SQL и их версионный payload. HTML содержит
  доступные цели, требования, награды и редакторские материалы. Каталог содержит обычные
  ссылки и ограниченную пагинацию. Личного прогресса в публичном ответе нет.
- `EntitySeo` формирует исходный HTML предметов, боссов, рейдовых карт, документов и
  справочных каталогов из текущих CONTENT_DIRECTORY/SQL. Названия, описания, ключевые
  характеристики и ссылки доступны без JavaScript. Каталоги ограничены 100 записями
  на страницу; архивные и удалённые карточки возвращают 404, включая старые URL из dist.
- Worker проверяет API даже для URL, уже имеющегося в dist. Снятая с публикации запись
  получает 404; ошибка origin — 503 и Retry-After, без устаревшего HTML. Пользователи
  и роботы получают одно содержимое. JS сохраняет метаданные при переходах.

Общий прелоадер скрывает незавершённый интерфейс до окончания bootstrap. При включённом
JavaScript дублирующие `.seo-reading` в интерактивных разделах скрыты стилями; исходный
HTML и метаданные сохраняются. Без JavaScript или при ошибке остаётся серверное содержимое.
Документы и страницы пагинации снимают прелоадер после разбора HTML, не ожидая отсутствующий
bootstrap. Анимация учитывает `prefers-reduced-motion`; при ошибке доступна кнопка повтора.
- `/sitemap.xml` объединяет `/sitemaps/pages.xml`, `/sitemaps/quests.xml` и отдельные
  карты предметов `items-pve.xml`/`items-regular.xml`. Режимы не рекламируют отсутствующие
  карточки друг друга. Карта квестов строится по действующим опубликованным записям,
  lastmod — updated_at в UTC.
  ID-алиасы, кабинет, ошибки и встроенные карты исключены.
  Для остальных сущностей sitemap учитывает актуальные архивы наборов данных.
  Текущие HTTP-статусы и HTML игровых карточек проверяются сервером при каждом запросе.
- `site:export` создаёт robots.txt, статические sitemap и SEO-экспорт для всех физических
  страниц. Проверка свежести запрещает сборку из устаревшего экспорта.
- `noindex` закрывает личные и служебные страницы. robots.txt не заменяет авторизацию.

## Совместимость и публикация

Сначала публикуется API, затем Worker/экспорт. Старый Worker продолжает работать с новым API.
Новый Worker при JSON 404 неизвестного endpoint старого API сохраняет прежнее поведение;
это совместимость релиза, а не подтверждение SSR. Ответ `seoVersion: 1`/404 всегда означает
отсутствующую страницу и не подменяется dist. Proxy ограничен семью секундами и двумя МиБ,
не пересылает cookie/Authorization; персональная шапка использует отдельный существующий путь.

Миграций и изменений аккаунтов нет. Откат — предыдущий код и согласованный экспорт;
он возвращает прежние ограничения индексации, без отката данных. Перед публикацией нужны
проверки AGENTS.md, включая MariaDB. Затем проверить HTTP/HTML квестов PVE/PVP, алиас,
robots, sitemap, 404/503. Серверные изменения контента проверять только разрешённой
тестовой записью с последующей очисткой.

## Яндекс.Вебмастер и контент

Файл подтверждения `yandex_78b9cda6dd2aaa25.html` экспортируется из
`resources/views/verification/yandex.blade.php`. Worker отдаёт точный адрес `.html`
с кодом 200 без автоматического редиректа, обращения к API или личной навигации.
Проверочный файл имеет `X-Robots-Tag: noindex` и не входит в sitemap.

После подтверждения прав добавить точный HTTPS origin в Яндекс.Вебмастер, отправить
sitemap, проверить robots и ответ сервера, запросить переобход важных квестов и торговцев.
Сохранить исходные показатели: страницы в индексе, причины исключения, показы, клики,
CTR и среднюю позицию по группам запросов. Сравнивать после фактического переобхода.

Развивать оригинальные материалы: цели текущей версии игры, маршрут, ключи, скриншоты
ориентиров, условия открытия и ветвления. Дату проверки добавлять только после проверки.
Не копировать тексты конкурентов и не создавать фиктивные FAQ/рейтинги. Одноимённые
предметы различать фактическими характеристиками, не техническими ID в заголовках.
